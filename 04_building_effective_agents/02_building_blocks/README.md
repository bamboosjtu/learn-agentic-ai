# 构建模块：Agentic 系统中的增强型大语言模型

## 引言

Agentic 系统是一类 AI 系统，在这类系统中，LLM（大语言模型）能够自主决定如何达成目标，包括使用哪些工具、收集哪些信息，而不是沿着一个僵化、预定义的脚本执行。在复杂任务中，单靠一个 LLM（即使是很大的模型）通常也不够，因为现实世界中的查询往往需要最新知识、更长链路的推理，或超出模型内部能力范围的专门计算。比如，回答一个细致的分析型问题，可能需要进行**规划**、使用**记忆**、调用**不同工具**，并将问题拆解成多个子部分。为了解决这些需求，现代基于 LLM 的 Agent 通常会在核心 LLM 之外接入外部模块，例如检索、工具和记忆。简而言之，*LLM Agent* 本质上就是一个被增强后的 LLM：它具备更复杂的推理能力、集成记忆能力，以及通过工具执行任务的能力。这些增强弥补了独立 LLM 的关键局限，例如上下文窗口有限、知识截止固定、无法与外部系统交互等，从而使 LLM 能够处理更复杂、更动态的任务。

**检索**、**工具**和**记忆**，是 Agent 架构中增强 LLM 能力的三个基础模块。检索增强把 LLM 连接到外部知识源（文档、数据库或网络），使其能够按需获取最新信息或领域专属信息，而不必只依赖训练数据。工具增强允许 LLM 调用外部程序或 API，例如执行计算、运行代码、查询数据库或调用 Web 服务，这实际上让模型能够“对外部世界采取行动”并获得新的结果。记忆增强则使系统能够在超出 LLM 内置上下文窗口的时间尺度上保留并回忆信息，从而缓解所谓的“数字失忆”问题，也就是 AI 无法记住过去交互的现象。接下来的章节将介绍增强型 LLM Agent 的架构，并说明**检索**、**工具使用**和**记忆**如何在推理过程中与 LLM 集成，从而显著扩展它的解决问题能力。

## 增强型 LLM 的架构概览

![](block.webp)

图 1：Agentic 系统中**增强型 LLM**的概念架构。位于中央的 LLM 是 Agent 的核心，接收用户输入并生成输出。它与三个关键模块相连：**检索**系统、一组外部**工具**以及**记忆**存储。在推理过程中，LLM 可以向检索模块发送查询并接收相关信息（虚线箭头 “Query/Results”），调用外部工具并获取返回值（“Call/Response”），也可以从长期记忆中读取信息或向其中写入信息（“Read/Write”）。这种设计使 LLM 能够动态引入知识、执行动作，并在原生能力范围之外存储或回忆信息。

这个架构的核心是 **LLM Core**，它在处理任务时负责生成计划和决策。但它并不是孤立工作的，而是通过明确设计的接口接入外部模块（如图 1 所示）。每当 LLM 判断需要额外信息或需要执行某个动作时，它都可以在*推理过程中间*调用这些接口。模型的提示词会被设计成告知它有哪些可用工具和检索 API，并把相关记忆上下文纳入其中。当前较先进的模型已经能够主动使用这些增强能力。例如，当 LLM 需要更多数据时，它可以自己生成搜索查询；它可以从工具箱中选择合适工具；也可以决定将当前交互中的哪些信息写入长期记忆，以备后续使用。通过针对具体场景定制这些能力，并为每个模块提供清晰的接口，就可以构建出一个*可组合、模块化的 Agent*，使其能够在单次推理会话中灵活调用不同功能。

增强型 LLM 架构可以看作 Agentic AI 系统的基础构件。在这种设计中，LLM 依然是决策大脑，但检索、工具和记忆模块扩展了它的能力边界。下面几节将更深入地展开这些组件，说明它们各自的角色，以及它们如何与 LLM 协同工作以提升整体表现。

## 检索增强

**检索增强**是指将外部信息检索系统（例如搜索引擎或文档向量数据库）整合进 LLM 的推理循环中。这使 LLM 能够访问训练之外的**支撑性数据**。在检索增强架构中，模型可以向知识库发出查询，并获得相关文档或事实，再据此生成信息更充分的回答。微软对 RAG（Retrieval Augmented Generation，检索增强生成）的描述很好地概括了这一点：它是一种“通过加入信息检索系统为大语言模型提供支撑数据，从而增强模型能力”的架构。换句话说，通过按需获取最新信息或上下文相关信息，检索增强可以确保 LLM 的回答建立在可靠、当前的知识来源之上，而不只是依赖静态训练语料。

检索的实现方式有多种。一种常见方式是使用**向量存储**：先将文档索引为嵌入向量，查询时再为用户问题生成嵌入，以查找语义上最相关的文档。然后将最相关的片段注入到 LLM 的上下文（Prompt）中，作为参考材料。这个过程让模型能够以受控方式访问事实信息，从而使回答更有依据。比如，若用户询问某家公司最新财报的细节，Agent 可以先将问题向量化，再从内部财报数据库中检索最相关段落，并将这些内容提供给 LLM。这样，LLM 就能基于必要事实给出更准确的回答。更重要的是，检索步骤还可以迭代进行或逐步细化：LLM 可能先做一次宽泛搜索，阅读结果后，如果有需要，再生成更具体的后续查询。编排系统（有时也称为 *agent core*）负责协调 LLM 与检索子系统之间的交互，但从 LLM 的视角看，它就像拥有了对相关事实的扩展记忆。检索增强显著拓展了 Agent 的知识范围，使其具备**访问最新信息、获得领域专长（通过索引专有数据）、以及为推理过程提供证据支撑**的能力。

## 工具增强

**工具增强**允许 LLM 通过调用外部工具或 API 来执行动作和计算。工具本质上是在 LLM 文本预测能力之外定义的一组操作，例如计算器、代码解释器、数据库查询接口、网页搜索 API、翻译服务，甚至对其他 AI 模型的调用。通过为 LLM 配备一套工具，并告诉它如何使用这些工具，就可以让它**在语言建模之外扩展功能能力**。在 Agentic 系统中，工具被视作 LLM 在适当时机可以调用的离散技能。例如，如果任务是一个包含数学计算的复杂分析，LLM 可以调用计算工具；如果需要实时信息（天气、股价等），LLM 可以调用 Web API；如果需要分析图片或运行代码，则可以使用专门工具。每个工具通常都有明确的接口定义（例如函数签名或 API 端点），而 Agent 会在提示词或配置中获得关于工具功能及调用方式的说明。

当 LLM “决定” 使用某个工具时，它会输出一个特殊的**动作**，通常是结构化格式，用来指明要调用哪个工具以及输入参数是什么。Agent 框架或编排器会检测到这个动作，执行对应工具，然后把工具输出（也就是**观察结果**或返回值）送回 LLM 的上下文。之后，LLM 便可以将这个结果纳入后续推理并继续完成任务。这个循环可以多次重复，并在不同工具之间切换，直到任务完成。从本质上说，LLM 加工具的组合使模型能够*与环境交互*：它可以向外部世界发问并获得结果，就像人在解题时会去查数据库或用计算器一样。工具通常以第三方 API 或允许 Agent 执行的代码形式实现，因此一个 Agent 的“工具箱”里可能同时包含搜索引擎 API、Python 解释器、天气服务和自定义数据库查询函数。

工具的使用显著提升了 LLM 的能力。它为那些 LLM 单独处理时容易出错的子任务提供了可靠性和精度，例如算术计算或精确逻辑运算，也让模型能够访问**实时数据或特定数据**，而这些数据并不在训练集中。更关键的是，工具使用与 LLM 的推理过程是紧密耦合的：何时需要工具、该用哪个工具，都是由 LLM 根据当前任务动态决定的。通过将工具能力接入 LLM，我们得到的是一个能够**采取行动**的 Agent，而不仅仅是一个会说话的模型。它可以执行多步骤流程、获取外部证据、完成计算，并把这些结果整合进对用户的连贯回答中。

## 记忆增强

**记忆增强**为 LLM Agent 提供了在长对话或跨多次会话中保留信息的能力，从而弥补 LLM 内置上下文窗口有限且短暂的限制。在增强型架构中，Agent 会配备一个**记忆模块**，用来存储重要信息（如对话历史、先前获得的知识、中间结果等），并在需要时将其取回。这可以看作是 Agent 关于交互和经验的扩展记忆或知识库。这类系统中的记忆一般分为两种：

* **短期记忆（Short-Term Memory）：** 这是 Agent 在单次对话或单次查询过程中维护的临时上下文。它可能包含最近几轮对话、LLM 当前已经产生的推理链（即模型近期的“草稿板”式思路与动作），以及任何中间结果。短期记忆通常通过在 Prompt 中保留最近消息或步骤来实现，因为只要内容还在当前上下文里，LLM 就能够“记住”它们，直到达到 token 限制。它相当于当前任务的工作记忆，也就是回答当前问题时的*“思维轨迹”*。

* **长期记忆（Long-Term Memory）：** 这是一个持久化的知识与历史交互存储，即使上下文窗口已经超出、甚至跨会话之后，Agent 也仍然能够依赖它。长期记忆可以是一个对话嵌入向量数据库、历史对话日志，或者任何记录 Agent 认为重要内容的结构化数据库。它可以跨较长时间尺度保留 Agent 的过往行为、学到的事实或先前任务结果。例如，在解决一个问题或回答一个问题之后，Agent 可以将解法摘要或关键事实写入向量存储。之后，如果再出现相关问题，Agent 就可以通过语义相似度搜索取回这些内容，从而提醒自己之前掌握过的相关知识。

一个健壮的记忆模块通常会同时结合短期记忆和长期记忆，这种方式有时也被称为**混合记忆（hybrid memory）**。在实践中，当新的用户查询到达时，Agent 会先查询自己的长期记忆存储（使用查询文本或其嵌入），以获取过去对话或数据中与当前任务相关的记录。然后这些结果会作为上下文加入 Prompt 中，这个过程有时也称为基于相关记忆的上下文增强。在整个推理过程中，Agent 的短期记忆，也就是它当前的思考过程和近期对话，会持续保留在 Prompt 中。在交互结束后，Agent 还可以提炼并保存新的信息到长期记忆中，以便未来使用。通过在推理开始时从长期记忆中**读取**，并在交互结束后向其中**写入**，LLM Agent 就能够有效地**长期记住重要信息**。这使得系统可以跨会话保持连续性，并在某种程度上实现累积式学习，不会反复忘记以前的讨论内容或查过的事实。记忆增强因此对很多应用至关重要，例如需要记住用户偏好的个人助理，或逐步积累知识的研究型 Agent。它让 AI 不必在每次查询时都从零开始，而是能随着时间建立自己的内部知识库，从而缓解无状态语言模型固有的“失忆”问题。

## 推理流程与组件交互

当检索、工具和记忆这些核心组件都具备后，增强型 LLM 的工作方式就变成了一个**交互式推理循环**，它能够规划、执行、观察和记忆。Agentic 系统中的推理过程是一种循环式工作流，其中 LLM 及其增强模块会持续相互提供输入和反馈。处理一个复杂用户请求或任务时，一个典型的推理过程大致可以概括为以下步骤：

1. **初始上下文组装：** 系统接收到用户请求。随后，在 LLM 开始生成回答之前，Agent 会先从记忆中**检索相关上下文**。例如，它会通过语义搜索，从长期记忆存储中取出与用户问题相关的事实或过往对话。最相关的记忆条目会被加入 Prompt；如果适用，还会加入近期对话窗口（短期记忆）以及可用工具的列表或说明（让 LLM 知道有哪些工具、如何调用它们）。这样组装出的 Prompt 包含了用户问题、检索到的背景信息、工具文档以及系统指令，然后交给 LLM 开始处理。

2. **LLM 推理与工具调用：** LLM 处理 Prompt 并开始生成输出。在 Prompt 和内部推理逻辑的引导下，LLM 可能会判断：要有效回答这个问题，它还需要额外信息，或者需要执行某个操作。这时，模型可以先形成一个**计划**（通常体现在其思维链中），然后输出一个**动作**。这个动作可能是调用某个工具，也可能是发起一次检索。例如，LLM 可能会输出类似：`Thought: 我应该先查一下最新市场数据。Action: Search["Company X 2025 Q2 earnings results"]`。这种“先推理，再行动”的方式正是 ReAct 框架的典型特征，也就是在输出中交替出现 *Thought → Action → Observation*。在这里，LLM 明确调用了 **Search** 工具，并传入查询字符串。

3. **工具执行（Act）与观察（Observation）：** Agent 控制器拦截 LLM 的动作并执行相应工具。如果是检索动作，这一步就可能是把查询发给搜索引擎或数据库并拿回文档；如果是其他工具，比如计算器或代码执行器，则意味着执行对应操作并获取结果。工具执行结果随后会作为**观察结果**返回给 LLM。通常会以标准化格式追加到上下文中，例如：`Observation: [搜索结果或工具输出]`。这实际上是用从环境中获得的新信息更新了 LLM 的短期记忆。LLM 不会从头重新开始，而是在已有上下文基础上继续同一轮推理。

4. **迭代式推理循环：** 在获得工具返回的新信息后，LLM 会继续推理。此时它可能已经掌握了回答问题所需的数据，也可能会判断还需要更多步骤。例如，它可能会继续输出：`Thought: 搜索结果表明我还需要计算增长率。Action: Calculator["(2025_revenue - 2024_revenue)/2024_revenue"]`。这种工具执行与观察反馈的循环可以重复多次，让 Agent 将复杂任务拆解为多个更小的操作步骤。在整个循环过程中，**短期记忆**，也就是到目前为止累积下来的思考、动作和观察，会不断在上下文中增长，使 LLM 能够“记住”本次会话里自己已经做过什么、学到了什么。这种迭代过程会持续，直到 LLM 判断自己已经收集到足够信息，并完成了生成最终答案所需的全部计算和操作。

5. **最终答案生成：** 一旦 LLM 获得了所有必要信息，并完成了基于工具的子任务，它就会为用户生成最终输出。通常这会是自然语言回答，或者任务的完整结果。当 LLM 的输出表明这是最终答案，而不再是中间动作时，Agent 便会停止。例如，LLM 这时会直接回答最初的问题，并将沿途检索到的事实和执行过的计算整合进最终结论中。

6. **记忆更新：** 回答结束后，Agent 可以将新的有用信息写入长期记忆。这可能包括刚刚发生的整段对话（让 Agent 记住自己已经回答过这个问题），也可能包括在过程中发现的特别重要的数据。把交互内容的摘要或向量化表示存储起来，可以让 Agent 在将来需要时重新召回这次经历。记忆模块还可能为这些内容打上关键词或元数据标签（例如 “earnings report analysis”），以便后续更高效地检索。通过把本次交互中的关键成果写入记忆，Agent 就相当于从任务中*学到*了东西，并逐步积累自己的知识。这样，当以后再次遇到相关问题时，它就不必重复所有相同步骤，而是可以复用过往成果。

在整个推理循环中，LLM 实际上是在编排全流程：它基于当前对话状态和现有信息，决定接下来该做什么（提什么问题、调用什么工具）；外部模块则负责执行这些步骤并把结果反馈回来。**规划、工具使用和记忆**的紧密结合，使 Agent 可以处理远超单次 Prompt-Response 范式能力范围的任务。它能够以一种**决策 - 行动 - 观察 - 修正**的循环方式处理复杂问题，类似人类在解决难题时会一边思考、一边查资料、一边用工具。这样的设计带来了更**准确、上下文感知更强、支持多步骤任务**的 AI 行为。由于它还能记住自己做过什么、学到了什么，系统也能保持连续性并避免重复操作。总结来说，检索、工具和记忆共同构成了 LLM 推理过程的扩展：*检索*赋予它知识，*工具*赋予它行动能力，*记忆*赋予它持久性。

## 结论

通过将检索、工具和记忆接入 LLM，已经形成了构建高级 AI Agent 的一个强大范式。这种架构保留了大语言模型在生成和推理方面的优势，同时通过与外部系统集成来弥补其局限。**检索增强**确保 LLM 能始终访问与当前任务相关、且最新的真实数据，而不是只依赖训练时学到的内容。**工具增强**赋予 LLM 在外部世界中执行动作的能力，无论是计算公式、运行数据库查询，还是调用 Web 服务，都能够扩大它可处理任务的范围，并提高结果的准确性与可靠性。**记忆增强**则提供了长期上下文感知能力，使 Agent 能够跨时间和复杂对话持续保留知识与经验，而不是每次响应后都“清空记忆”。

在 Agentic 系统中，这些组件会在推理过程中协同工作：LLM 会动态决定何时接入检索系统、某个子任务该调用哪个工具，以及哪些信息应当从记忆中读取或写入记忆。本文描述的概念架构展示了一种以 LLM 为中心的设计，模块化增强能力在运行时插入，扩展模型的能力边界。借助这些增强，LLM Agent 可以**规划**并拆解复杂问题、**查阅外部知识库**、**执行专门化操作**，并且**记住重要信息**，所有这些都发生在同一个集成工作流中。由此得到的是一个更强大、更灵活的 AI 系统，它能够处理那些未经增强的 LLM 根本无法完成的真实世界任务。随着基于 LLM 的 Agent 持续演进，检索、工具使用和记忆集成这些原则，仍将是构建此类系统的核心。它们不仅让系统“懂语言”，更让系统在复杂环境中具备*主动达成目标的能力*。因此，增强型 LLM 架构代表了迈向新一代 AI Agent 的关键一步，这类 Agent 能够围绕目标进行推理、采取行动并持续学习，同时结合大模型的生成优势和外部系统的精确能力，取两者之长。
