## 什么是“工具”（在 AI 里）？

**工具**是一个**小型助手**，专门把某一项任务做好（比如计算器或天气应用）。
你的 AI（“大脑”）可以**请求**工具去完成这项任务，然后再利用结果回答你。

> **一句话版：** *工具就是 AI 用来完成具体事情的助手。*

---

## 什么是“工具调用”？

**工具调用**指的是 AI 在对话过程中**决定使用某个工具**。

**流程：**

1. **用户提问：** “Karachi 的天气怎么样？”
2. **AI 思考：** “我需要实时天气数据。”
3. **AI 调用工具：** `get_weather(city="Karachi")`
4. **工具返回：** `{"temp": 33, "condition": "Cloudy"}`
5. **AI 回答：** “Karachi 现在 33°C，多云。”

你可以把它理解成学生在考试时使用**计算器**：学生决定什么时候用它，输入数字，得到结果，再用自己的话写出最终答案。

---

## 为什么我们需要工具？

* **LLM 没有实时数据。** 工具可以获取当天的事实信息，比如天气、新闻、价格。
* **LLM 不能自己行动。** 工具可以真正“做事”，比如发邮件、预约时段、运行代码。
* **准确性与安全性。** 工具可以校验数学结果、查询数据库，或者执行规则约束。

---

## 常见工具类型（适合初学者理解）

| 工具 | 用途 |
| --------------- | ------------------------ |
| **搜索** | 在网上查找事实信息 |
| **计算器** | 进行精确计算 |
| **天气** | 获取实时天气 |
| **邮件/SMS** | 发送消息 |
| **代码运行器** | 安全执行代码 |
| **数据库** | 读写应用数据 |

## 三个现实世界类比

* **智能手机和 App：** 你的手机（AI）会在需要导航时打开地图（工具）。
* **厨房：** 厨师（AI）只会在食谱需要时使用搅拌机（工具）。
* **办公室：** 经理（AI）会向财务系统（工具）查询发票总额。

---

## 一次工具调用的完整生命周期（超简版）

1. **识别意图：** “这个问题需要外部帮助。”
2. **选择工具：** 挑一个合适的助手。
3. **填入参数：** 提供清晰、具体的输入参数，例如 `city="Karachi"`。
4. **运行工具：** 调用函数或 API。
5. **使用结果：** 用自然语言向用户解释结果。
6. **可选继续动作：** 如果需要，再串联调用下一个工具（比如接着发邮件）。

## 可以在课堂上演示的“纸面版”小实验（无需代码）

* 准备三张卡片（工具）：**计算器**、**天气**、**词典**。
* 分配角色：一位学生扮演 **AI**，三位学生扮演**工具**，再找一位扮演**用户**。
* 用户提问： “19×23 等于多少？Karachi 的气温是否高于 30°C？”
* “AI” 决定：

  * 调用 **计算器**，得到 `437`。
  * 调用 **天气**，得到 `33°C`。
* “AI” 回答： “19×23 = 437。是的，气温高于 30°C（33°C）。”
  这样能把工具调用过程直观地展示出来，也更有趣。

## 一个工具在概念上长什么样？

你需要定义**名称**、**输入**和**返回值**。例如：

```
Tool name: get_weather
Inputs: city (text)
Returns: { temp: number, condition: text }
```

当 AI 识别到这是天气问题时，就会选择这个工具，并从用户消息里提取 `city` 参数。

---

## 什么时候该用工具，什么时候不该用？

* **该用工具：** 获取实时信息、做精确计算、读写数据库、发送消息，或者执行真实操作。
* **不该用工具：** 如果普通解释、讲故事或概念性回答已经足够，就不需要工具。

---

## 初学者构建工具时的好习惯

* **一个工具只做一件事**（单一职责）。
* **名称和输入要清晰**，例如 `send_email(to, subject, body)`。
* **输出要可预测**（简单 JSON）。
* **处理错误情况**（比如城市没找到怎么办）。
* **注意安全**（不要暴露密钥；要校验输入）。
