# 对话式 AI 与 Agentic AI：你通往智能系统的起点

## 引言

欢迎来到令人兴奋的 AI 世界，在这里，机器开始学会以智能的方式进行交互和行动。我们将聚焦两个核心方向：**对话式 AI（Conversational AI）** 和 **Agentic AI**。你可以把对话式 AI 理解为 AI 的“声音”部分，也就是让你能够像与真人交流一样，自然地与聊天机器人、虚拟助手等系统对话的能力。

但 AI 正在超越“只会说话”的阶段。**Agentic AI** 更进一步，它不仅仅是回复你，而是能够为了实现目标，自己思考、决策并采取行动。换句话说，它不只是“回应”，而是能主动“做事”。

举个例子：一个对话式 AI 可以根据你的喜好推荐一部好电影；而一个 Agentic AI 则可能进一步帮你买票、下单零食外卖，甚至把观影安排加入日历，而你在最初提出请求之后几乎不需要再动手。

这两类强大的 AI 都由 **大语言模型（LLMs）** 驱动。它们是整套系统的“大脑”——基于海量文本训练而成，能够以非常高的流畅度理解并生成人类语言。

这份指南就是你的路线图。它会带你从容易上手的对话式 AI 开始，逐步构建属于你自己的 AI 学习平台，然后升级到能够在真实世界中使用的强大 Agentic AI 系统。过程中，我们也会解释 LLM、工具使用协议、AI Agent 等关键概念，尽量保持清晰、实用，并把重点放在“让你动手做出来”上。

## 打好基础：构建对话式 AI 学习平台

先从一个简单直接的对话式 AI 平台开始。我们的目标是搭建一个**非常容易上手、也非常适合实验**的学习环境，即使你是 AI 新手也能快速进入状态。下面是我们选用的关键技术，以及选择它们的原因：

- **现代包管理工具（如 uv）**
  忘掉那些混乱安装过程带来的烦恼。我们使用类似 `uv` 这样的高速包管理器来管理 Python 库依赖。你可以把它理解成一个效率极高的安装工具，它能快速把项目所需组件全部装好，减少各种环境问题。这样你就能把更多时间花在学习和构建 AI 上，而不是卡在环境配置里。

- **轻松搭建聊天界面（如 Chainlit）**
  想在几分钟内，而不是几周内，做出一个聊天界面？我们会借助 Chainlit 这类友好、开源的库，用极少代码快速搭建漂亮的交互式聊天 UI。它们就是为对话式 AI 设计的，让你能直接把模型能力呈现在网页聊天窗口里，把注意力集中在 AI 如何响应用户，而不是纠结复杂的前端开发。

- **统一接入 LLM（通过 LiteLLM 等工具）**
  想象一下，有一把钥匙能打开几乎所有主流 LLM 的大门，这就是 LiteLLM 这类工具的意义。它提供了一种统一方式，让你可以连接 Google、OpenAI、Hugging Face 等不同来源的模型。这让你可以更灵活地实验不同模型、比较它们的优缺点，并在不重写代码的情况下快速切换模型。

- **先进且易用的 LLM（如 Google Gemini 家族）**
  在平台核心智能上，我们推荐使用一个功能强、且免费额度友好的先进模型，例如 Google Gemini 系列。它们既足够强大，又易于获取，非常适合作为学习起点。你可以从第一天起就接触高级 AI 能力，而不必承担太高的门槛。当然，你也可以尝试开源模型，但为了获得更平滑的学习体验，优先选择那些易用且自然语言表现优秀的模型会更好。

- **用工具扩展 LLM 能力（通过 MCP 或 Function Calling）**
  LLM 很强，但如果它不仅能聊天，还能真正“做事”呢？这里我们会引入 Model Context Protocol（MCP），或者更常见的说法——“Function Calling” / “Tool Use”。这种方式让你可以把 LLM 与外部信息和工具系统化连接起来。你可以把它理解为：给 AI 增加上网搜索、使用计算器、查询数据库、控制其他软件的能力。这是从“聊天机器人”走向“真正有用的 AI 助手”的关键步骤。

- **可移植、可分享的平台（配合 Docker 与云部署）**
  我们还希望你构建出来的 AI 不只是跑在自己电脑上，而是能方便分享和部署。为此我们使用 Docker 把应用打包成容器。你可以把 Docker 理解为一个自包含的盒子，里面装着你的 AI 应用以及它运行所需的一切。无论你把它放到自己电脑、朋友电脑，还是云端，运行结果都应一致。部署方面，我们会用 Google Cloud Run 或 Azure Container Apps 这类云服务，它们能轻松托管 Docker 容器，并自动扩缩容，让你的 AI 应用更容易上线给别人使用。

## 上手实践：一步步构建你的对话式 AI 平台

下面是搭建基础对话式 AI 平台的步骤。注意，我们会一直坚持“先简单、后扩展”的原则。

1. **准备 Python 环境**
   确保你已经安装了 Python。接着安装现代包管理工具，比如 `uv`。你可能一开始会用标准命令 `pip install uv` 来安装它。安装完成后，创建一个新的项目环境，例如 `uv new ai-platform`，让项目结构更整洁，也避免不同项目之间相互污染。

2. **安装 AI 工具链**
   使用新的包管理工具快速安装核心依赖。例如在项目目录中运行：

   ```bash
   uv install chainlit litellm
   ```

   这条命令会快速安装 Chainlit（聊天界面）和 LiteLLM（统一接入 LLM），以及相关依赖。

3. **编写你的第一个聊天应用**
   新建一个 Python 文件，比如 `app.py`。导入 Chainlit 和 LiteLLM，然后定义一个函数来处理用户消息。下面是一个简化示例：

   ```python
   import chainlit as cl
   from litellm import completion

   @cl.on_message
   async def handle_message(message: str):
       user_input = message  # 用户输入的消息
       response = completion(model="gemini-pro", prompt=user_input)  # 把输入发给 LLM
       await cl.Message(content=response).send()  # 把 LLM 的回复显示到聊天界面
   ```

   这个例子做了三件事：接收用户输入、发送给模型、把模型回复显示出来。`@cl.on_message` 装饰器会自动把这个函数连接到 Chainlit 聊天界面，因此实现起来非常简单。

4. **连接你的 LLM**
   要让应用真正跑起来，你还需要连接所选模型，例如 Gemini。通常这意味着获取 API Key，或者通过某个平台访问模型。例如 Google Cloud AI Platform 提供 Gemini 模型接入。你通常需要通过环境变量或配置文件安全地保存这些凭据。LiteLLM 简化了这一步，让你只需要指定模型名，它会帮你处理底层 API 通信。

5. **在本地启动聊天机器人**
   在终端运行：

   ```bash
   chainlit run app.py
   ```

   Chainlit 会启动本地 Web 服务，并自动在浏览器中打开聊天界面，通常地址是 `http://localhost:8000`。你会看到一个简洁的聊天窗口。试着输入一句话，比如 “Hello AI, what can you do?”，然后观察模型直接在界面里回复你。到这里，你已经完成了自己的第一个对话式 AI。

6. **用工具增强能力（可选，但推荐）**
   现在可以让聊天机器人更聪明一点。比如，如果机器人遇到数学题，不再是“凭印象猜”，而是真正调用一个计算逻辑得到准确结果。你可以修改 `handle_message`，识别数学类请求后用 Python 计算，再返回结果。这个简单例子已经能说明工具使用的威力。在真实项目中，工具使用会通过 MCP 或 Function Calling 更正式地接入，让 LLM 学会自己判断何时使用外部工具。

7. **用 Docker 打包应用**
   为了让应用更便携、更易部署，在项目目录中创建一个 `Dockerfile`：

   ```dockerfile
   FROM python:3.10-slim # 从轻量级 Python 镜像开始
   WORKDIR /app # 设置容器中的工作目录
   COPY . /app # 把项目文件复制到容器中
   RUN pip install uv && uv install chainlit litellm  # 安装依赖
   CMD ["chainlit", "run", "app.py", "-p", "80", "--headless"] # 启动 Chainlit
   ```

   这个 Dockerfile 会完成 Python 环境配置、复制代码、安装依赖，并在容器中运行 Chainlit。之后你可以通过下面的命令构建镜像：

   ```bash
   docker build -t my-chatbot .
   ```

8. **部署到云端**
   现在，把你的 Docker 容器发布到云上。Google Cloud Run 和 Azure Container Apps 都很适合这类任务。你可以用它们的 CLI 或 Web 控制台来部署镜像。这些平台会负责托管、扩缩容，并给你一个可访问的网址。对于 Google Cloud Run，甚至可以用类似 `gcloud run deploy --source .` 这样的命令一键构建和部署。几分钟内，你的对话式 AI 就可能已经在互联网上可访问了。

在上面的整个过程中，我们始终优先考虑“简单”。快速包管理、轻量 UI、统一 LLM 接入、简化云部署，这些都是为了让你把精力放在 AI 概念和实践上，而不是掉进技术配置的坑里。完成这一阶段后，你将拥有一个从头到尾自己构建、并且真正理解其运行方式的对话式 AI 平台。

接下来，我们会在这个基础上，进一步升级为更强大的 Agentic AI 系统。

## 走向生产：Agentic AI 系统

拥有一个能聊天的机器人已经很不错了，但更进一步想象一下：如果 AI 能主动替你做事，而不仅仅是聊天，会怎样？这就是 **Agentic AI** 的跃迁。Agentic AI 让 AI 可以为了达成目标，自主决策、使用工具、采取行动。这是 AI 从“交互式”走向“行动式”的关键一步。

随着 AI 的演进，它的价值越来越不只体现在“会说”，而是体现在“会做”。Agentic AI 的目标，是构建真正能够代表我们完成复杂任务和自动化工作流的智能助手。

为了构建一个可用于生产的 Agentic AI 系统，我们需要在对话式基础上引入更高级的框架和架构。对话式 AI 平台将成为更大系统中的一个组成部分。下面是新增的关键技术和选择原因：

- **多 Agent 编排框架（如 CrewAI、Microsoft Autogen、LangGraph）**
  为了管理 Agentic 行为的复杂性，我们需要使用专门的多 Agent 协作框架。可以把它理解为：多个不同专长的 AI Agent 组成一支团队，共同解决问题。

  - **CrewAI**
    CrewAI 专为创建“Agent 团队”设计。每个 Agent 可以承担不同角色，并围绕共同目标协作。它简化了复杂的 Agent 协调过程，处理通信、任务委派和工具使用，并提供较高层抽象，降低开发多 Agent 系统的门槛。

  - **Microsoft Autogen**
    由 Microsoft Research 推出的 Autogen，是面向企业和研究场景的多 Agent 框架。它适合构建更复杂的交互，例如 Agent 之间通过对话推理问题，或让专门的子 Agent 分别处理特定任务。它强调结构化与负责任的 AI 开发，并与微软技术生态结合紧密。

  - **LangGraph**
    LangGraph 来自 LangChain 生态，用图（graph）的方式定义 Agent 行为，把动作、子 Agent、决策点都表示为图节点。它非常适合构建可靠、可持久化、有状态的 Agent 工作流，尤其适用于需要记忆管理、错误恢复，甚至人类介入的生产级场景。

- **基于容器化 FastAPI 的可扩展后端**
  一旦离开学习阶段，就不能只依赖开发用的轻量服务了。我们会用 FastAPI 构建一个高性能、可扩展的后端 API，并继续使用 Docker 进行容器化。这让你的 Agentic AI 后端能够像前面的聊天平台一样被稳定部署到云端。

  FastAPI 的优势在于：速度快、易于定义规范 API、适合并发请求处理，也具备认证、日志、异常处理等真实项目需要的能力。例如，在生产系统里，你往往希望暴露一个像 `/ask-agent` 这样的接口，供网页、移动端等不同客户端调用。

- **基于 Next.js 的灵活前端**
  在前端层面，我们会从 Chainlit 过渡到 Next.js。Next.js 是一个强大的 React 框架，能让你构建高度自定义的 Web 应用。在真实生产环境中，你通常会需要带品牌风格、带完整功能的界面，而不是仅仅一个默认聊天窗口。

  Next.js 支持现代 Web 开发模式，例如服务端渲染、与 FastAPI 后端顺畅对接，以及更自由的 UI 控制。这样，AI 不再只是聊天窗口里的一个功能，而是整个产品中的核心组件。

## 把它们串起来：Agentic AI 工作流

你可以把对话式 AI 界面理解为一个强大系统的入口。当用户提出复杂请求时，系统不再只是调用一次 LLM 返回答案，而是把请求交给后端的 Agentic AI 编排系统处理。你可以把这个后台想象成一个“控制室”，由 CrewAI 或 LangGraph 这类框架来管理。

在这个控制室里，一组专门化 Agent 会开始分工协作。一个“管理者”或“编排者”Agent 先把用户请求拆分成若干个子任务，然后交给专门 Agent 去执行。比如：

- 有的 Agent 擅长网页搜索
- 有的 Agent 擅长数据分析
- 有的 Agent 擅长写代码
- 还有的 Agent 负责验证结果

这些 Agent 会相互通信和协作，逐步找到解决方案。而“对话 Agent”则作为用户代理，确保整个交互仍然自然、连贯。整个过程中，系统会保留会话上下文，从而支持多轮交互。最终，编排者 Agent 汇总结果，并通过熟悉的聊天界面返回给用户。

举个例子，假设你对 Agentic AI 说：

> “帮我调研 5 万美元以下最适合家庭使用的电动车，并做一个对比表。”

后台可能会这样分配任务：

- **网页搜索 Agent**：收集电动车和价格信息
- **数据分析 Agent**：筛选出 5 万美元以下的车型，并提取适合家庭使用的关键特征
- **表格生成 Agent**：把结果整理成清晰的对比表

这些 Agent 会相互交换信息、不断修正结果，直到编排者 Agent 汇总出最终答案，并通过对话形式呈现给你。用户仍然只是在聊天，但系统的能力已经远远超出了普通聊天机器人。

## 从对话式 AI 过渡到 Agentic AI：一步步升级

如果你想把现有的对话式 AI 升级成真正的 Agentic AI 系统，可以按下面的路径推进：

1. **模块化你的代码**
   把现有对话式 AI 代码拆分成不同模块：UI、核心 AI 逻辑、模型接入层。学习阶段你可能把所有东西都写在 `app.py` 里，但进入生产阶段后，最好把 AI 决策逻辑放进独立后端服务（FastAPI），前端（Next.js）只负责界面和输入输出。

2. **用框架实现 Agent 逻辑**
   集成像 CrewAI、Autogen 或 LangGraph 这样的 Agent 编排框架。你需要定义不同 Agent 的角色和能力，例如对话管理、网页搜索、数据分析、知识检索，以及一个中心编排者来协调流程。

3. **接入对话上下文**
   确保用户的历史会话能够流入 Agent 系统。通常编排者 Agent 会接收用户的当前消息，而系统内的“对话 Agent”则负责维护整体对话记忆。这保证了系统依旧能像原来的聊天机器人一样进行多轮、有上下文的自然交互。

4. **开发 FastAPI 接口**
   用 FastAPI 暴露 Agentic AI 的能力。例如提供一个 `POST /agentQuery` 接口，接收用户输入，返回 Agent 系统生成的结果。接口内部会调用你选择的编排框架，触发完整 Agent 工作流。

5. **开发 Next.js 前端**
   使用 Next.js 构建更成熟的聊天界面，包括消息输入框、对话历史展示区，以及与 FastAPI 后端的 API 调用逻辑。这样你能拥有更强的 UI 可控性，比如品牌风格、用户认证、高级交互组件等。

6. **充分测试并持续迭代**
   对整个系统进行端到端测试：从 Next.js 前端的用户输入，到 FastAPI 后端，再到 Agent 核心逻辑，最后回到前端。先验证基础链路，再逐步优化角色定义、通信方式和错误处理。记录日志非常关键，而 LangGraph 这种图结构框架在调试 Agent 工作流时尤其有帮助。

7. **部署你的生产系统**
   把 FastAPI 后端容器化，并部署到 Cloud Run、Azure Container Apps 等云平台。前端可以部署到 Vercel，或者和后端一起容器化部署。如果前后端分属不同域名，还需要配置 CORS。进入生产环境后，也要记得加入 API Key、用户认证等安全措施，避免滥用。

通过这些步骤，你就能把一个简单聊天机器人，升级成一个真正强大的 Agentic AI 应用。用户表面上依然是在和一个聊天界面交互，但背后实际上运行的是一个具备多步推理、工具调用和自主行动能力的系统。

## 总结：你通往智能 AI 的旅程

最后，把这条路线再总结一下：

- **对话式 AI 与 Agentic AI**
  对话式 AI 擅长自然语言交互；Agentic AI 擅长主动行动和达成目标。两者结合之后，才能既有好用的交互体验，又有真正落地的任务执行能力。

- **面向学习的设计取舍**
  在学习阶段，我们优先选择上手快的工具：快速包管理、简单 UI、统一 LLM 接入、免费友好的强模型，以及工具使用概念。这些设计都是为了降低门槛，让你更快进入实战。

- **走向生产的 Agent 框架**
  在生产阶段，我们引入 CrewAI、Autogen、LangGraph 这类编排框架，搭配 FastAPI 后端和 Next.js 前端，构建可扩展、可维护的多 Agent 系统。对话界面依然保留，但它背后已经连接到更强大的 Agent 引擎。

- **真实世界的影响**
  Agentic 对话式 AI 正在改变很多行业。想象一下：客服 Agent 不仅能聊天，还能自主解决问题；个人助理不只是提醒你，而是真正帮你处理事务；AI 协作系统可以帮助团队加速软件开发。这些都说明 Agentic AI 正在推动复杂任务自动化。

- **你接下来的行动**
  继续深入 Agent 框架，例如尝试 CrewAI 或 Autogen 的教程，做一个多 Agent 摘要应用，或探索 LangChain / LangGraph 工具能力。进一步打磨 prompt engineering，因为它在 Agent 系统里依然重要。同时，也要重视 AI 安全和负责任开发。Agentic AI 很强大，因此必须在安全护栏、伦理和规范方面保持谨慎。

这份指南提供了一个偏高层、偏教程式的概览，帮助你建立对对话式 AI 和 Agentic AI 的整体认知。现在，你已经拥有一个很好的起点，可以开始构建自己的智能应用了。先从简单开始，在实践中不断迭代，然后逐渐加深复杂度。AI 开发是一个快速发展的领域，你掌握的每一个组件——从让聊天机器人会说话，到让 Agent 真正会行动——都会开启新的可能性。

开始你的 AI 构建之旅吧。
