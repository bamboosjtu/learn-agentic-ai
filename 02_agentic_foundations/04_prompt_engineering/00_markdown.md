# 面向 LLM 的 Markdown

大型语言模型可以生成并理解多种格式的输出。不过，Markdown 已成为一种方便的默认选择，主要有以下几个原因：

**1. 可读性：** 与原始 HTML 相比，它对人类更友好，并且可以快速渲染标题、粗体/斜体文本、项目符号列表等内容。

**2. 简洁性：** 无论是对人还是对下游应用（例如聊天界面，或将 Markdown 转换为富文本的 API）来说，Markdown 都更容易书写和解析。

**3. 广泛支持：** 许多平台都原生支持 Markdown，因此它逐渐成为一种轻量格式化场景下的“最低通用标准”。

在实际使用中，并没有必须使用 Markdown 的硬性要求。它只是一个流行且对用户友好的默认格式，能够让输出在各种显示场景中都保持良好的排版效果。

Markdown 对于**编写提示词和组织输出内容**都很有帮助。以下是它在提示词编写中常见的优势：

**1. 清晰性与可读性：** Markdown 可以让你通过标题、项目符号、粗体或斜体等方式在视觉上区分不同部分并强调重点。这不仅方便你在编辑时阅读，也有助于模型识别结构线索。

**2. 组织复杂提示词：** 如果你有一个多部分提示词，例如先给出一组指令，再给出示例输入，最后补充约束条件，那么 Markdown 的标题和格式化能力可以帮助你把这些部分整理得更清晰。

**3. 一致性：** 使用统一格式（如 Markdown）来编写提示词，有助于你在不同任务或项目之间保持一致风格。这种一致性可能会间接帮助模型更好地响应相似结构的提示词。

**4. 便于协作：** 如果你需要和他人共享提示词（例如通过 GitHub 或其他基于文本的平台），Markdown 良好的可读性可以让协作者无需额外工具就快速理解内容和结构。

总体而言，Markdown 是一种非常适合用来编写提示词的干净、结构化方式，就像它同样适合用于组织输出内容一样。
